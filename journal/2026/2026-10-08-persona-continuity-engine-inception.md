# Persona Continuity Engine enters the Character Continuity Program

**Date recorded:** 2026-10-08. **Primary repository:** [Azimn/Persona-Continuity-Engine](https://github.com/Azimn/Persona-Continuity-Engine). **Role:** engineering candidate, not a new Pretorius or canonical memory store.

## Why this line exists

Attractomancy preserved ritualized persona sources and procedures, while [Attractomancy Loop](https://github.com/Azimn/Attractomancy-Loop-there-it-is) tests whether symbolic treatment outperforms semantically and volume-matched ordinary conditioning. The new engine investigates a different, practical question: can the same approved character specification be deterministically serialized into multiple source-grounded representational forms, then evaluated for consistency, restart reconstruction and transfer across replaceable model renderers?

This is distinct from neural-substrate learning (Pretorius Neural Network and BioCircuit), connective topology and retrieval (Pretorius Connectome), evolutionary phenotypes (Bicentennial Man), and canonical identity ownership (Kiki-Mind, Calibos and The Doctor Lives). The engine has no authority to record lived experiences or to rewrite subject-owned state. Its first fixtures are two synthetic characters, not Pretorius.

## Documentation and implementation provenance

The [M0 documentation commit](https://github.com/Azimn/Persona-Continuity-Engine/commit/7c7645038cdfec0774535b9f32991342688e5359) created the explicit [research lineage](https://github.com/Azimn/Persona-Continuity-Engine/blob/main/docs/LINEAGE.md), [architecture](https://github.com/Azimn/Persona-Continuity-Engine/blob/main/docs/ARCHITECTURE.md), [PersonaSpec v1](https://github.com/Azimn/Persona-Continuity-Engine/blob/main/docs/PERSONA_SPEC_V1.md), [evaluation boundaries](https://github.com/Azimn/Persona-Continuity-Engine/blob/main/docs/EVALUATION_PROTOCOL.md), and a [12-source commit-pin ledger](https://github.com/Azimn/Persona-Continuity-Engine/blob/main/research/source_pins.json).

Implementation began on [M1 code commit](https://github.com/Azimn/Persona-Continuity-Engine/commit/a875936a76b209d444cdfa695db7cf84c00c6e0f), followed by [fixtures, tests and CI](https://github.com/Azimn/Persona-Continuity-Engine/commit/08487bb4917995a5e03382eebeddf8a833fb589e). [GitHub Actions run 37874567188](https://github.com/Azimn/Persona-Continuity-Engine/actions/runs/37874567188) passed with twenty Python unit tests in both Python 3.11 and 3.12 jobs. The subsequent documentation/CI refinement is tracked by [run 37874666217](https://github.com/Azimn/Persona-Continuity-Engine/actions/runs/37874666217), which also completed successfully.

The packet compiler currently supports factual, narrative, symbolic and hybrid source-preserving framing. It provides canonical source, content and packet SHA-256 traceability and rejects unlinked evidence. It has no model inference, model-neutral behavioral scoring or memory-carrier mechanism yet. Its prompt lengths differ, so this initial code is not evidence of an information-matched effect.

## Research and engineering separation

The source catalog remains in Attractomancy. Le Refuge source claims and controls remain in Attractomancy Loop. Character histories and cognitive mechanisms remain in their production and research repositories. Persona Continuity Engine may receive approved read-only exports and create disposable conditioning packets. Its effectiveness needs separate held-out trials, with strong factual controls, external-state restart baselines, cost accounting and absent-memory rejection.

The next tracked gates are [M2 Ollama model interface](https://github.com/Azimn/Persona-Continuity-Engine/issues/1) and [M3 benchmark/restart test](https://github.com/Azimn/Persona-Continuity-Engine/issues/2). Do not export a persona-conditioning improvement to The Doctor Lives until independently measured and accepted behind its own production gates.

**Outcome as of this entry:** offline engineering artifact validated; no empirical claim that any conditioning strategy yields better continuity, persistent identity or subjective experience.

## M3 fixture pre-execution hardening (2026-10-08 Central time)

The PCE engineering line now has a separately sealed, source-grounded pilot design, anchored in [PCE main commit 6d38e1c](https://github.com/Azimn/Persona-Continuity-Engine/commit/6d38e1c2d893fe4955d59bf9ca1c5eef3f7939f0). [GitHub Actions run 37882570510](https://github.com/Azimn/Persona-Continuity-Engine/actions/runs/37882570510) passed on Python 3.11 and 3.12, including v1 source/probe/rubric/preregistration hash verification.

The two wholly synthetic examples (Meridian and River) were redesigned with explicit values, constraints, priorities, relationships, commitments and contrasting interests. The immutable [24-question pilot battery](https://github.com/Azimn/Persona-Continuity-Engine/blob/6d38e1c2d893fe4955d59bf9ca1c5eef3f7939f0/m3/probes.v1.json) has four retrieval, four multi-section integration and four conflict probes per persona. Every integration and conflict item records source field IDs, a normative expected resolution and a plausible one-field FACTUAL-only failure hypothesis. The hypothesis does not prejudge actual model responses.

The six-dimensional [0/2/4 scoring rubric](https://github.com/Azimn/Persona-Continuity-Engine/blob/6d38e1c2d893fe4955d59bf9ca1c5eef3f7939f0/m3/rubric.v1.json), [preregistered contrast/threshold plan](https://github.com/Azimn/Persona-Continuity-Engine/blob/6d38e1c2d893fe4955d59bf9ca1c5eef3f7939f0/m3/preregistration.v1.json), and [five-file SHA-256 seal](https://github.com/Azimn/Persona-Continuity-Engine/blob/6d38e1c2d893fe4955d59bf9ca1c5eef3f7939f0/m3/freeze.v1.json) were published before model testing. PCE can now compile natural length and individually target-tokenizer-matched packets using recorded, explicitly non-persona calibration filler, with a maximum 5% shortfall from the longest arm and no overshoot. This compiler implementation is not an empirical finding that padding is psychologically neutral.

The protocol plans 576 response slots per budget mode, 1152 across both modes, assuming two models, two personas, four arms, three independent starts and 12 probes/persona. This remains **an unexecuted exploratory pilot**. Exact target model/tokenizer revision, scorer calibration and the opt-in M2 runner remain prerequisites. No persona continuity benefit, model migration, hidden memory, or latent-state preservation is inferred. Results, positive or negative, will require their own pinned run artifacts.
